# Logging Pipeline Overview

This document describes the flow of log data in the Day 05 lab and how each component interacts.

```mermaid
graph LR
    A[systemd-journald] --> B[Plain text log files]
    B --> C[logrotate]
    C --> D[Compressed archives (.gz)]
```

## Components
- **systemd-journald**: Captures logs from the kernel, services, and user processes. In this lab we only read from the journal using `journalctl`.
- **Plain text log files**: Synthetic logs generated by `generate-synthetic-logs.sh` (e.g., `access.log`, `app.log`). These emulate typical application log files located under `lab-workdir/logs/`.
- **logrotate**: Manages rotation, compression, and retention of the plain‑text logs. The configuration `lab05-app.conf` is templated with the actual log directory at runtime.
- **Compressed archives**: After rotation, old logs are stored as `.gz` files (e.g., `access.log.1.gz`). These can be inspected with `zcat`/`zgrep`.

## Lab Steps
1. **Generate synthetic logs** – deterministic data placed in `lab-workdir/logs/`.
2. **Inspect logs** – `inspect-logging.sh` runs read‑only commands against the synthetic logs and the journal.
3. **Logrotate dry‑run** – shows what would happen without modifying files.
4. **Logrotate real run** – rotates and compresses the logs according to `lab05-app.conf`.
5. **Cleanup** – removes the temporary `lab-workdir` while preserving the `outputs/` directory with all result files.

---
*All commands are read‑only with respect to the host system; they operate only within the repository sandbox.*
